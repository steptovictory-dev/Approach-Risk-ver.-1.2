# PostgreSQL – хранение и загрузка данных

PostgreSQL хранит наблюдения и фиксированное разбиение по дням. Таблица `study_days` содержит сезон и split; `examples` содержит пары наблюдений и признаки. JOIN связывает их по аэропорту и дню

| Механизм | Что обеспечивает |
| --- | --- |
| PRIMARY KEY | Одно наблюдение на сочетание airport, event_id, origin_time |
| FOREIGN KEY | Для каждого наблюдения существует зарегистрированный день |
| NOT NULL и CHECK | Обязательные поля и допустимые временные границы |
| Временная таблица и COPY | Быстрый перенос исходных строк для проверки |
| Сравнение существующих строк | Измененные исходные значения вызывают ошибку |
| Одна транзакция | Ошибки загрузки и сверки отменяют изменения |

## Текущий локальный запуск

Из корня проекта:

```powershell
powershell -File scripts/postgres.ps1 status
powershell -File scripts/postgres.ps1 stop
powershell -File scripts/postgres.ps1 start
.\.venv\Scripts\python.exe scripts/database.py
```

Порт 55432, адрес 127.0.0.1. Сервер запускается вручную, без системного сервиса. Кластер в `data/postgres-cluster`, исполняемые файлы в `data/postgres-runtime/pgsql/bin`. Пароль в локальном `.env`; не выводить его в отчеты или терминал

Управлять сервером нужно от того же пользователя Windows, который его запустил. Песочница Codex может не видеть процесс другого пользователя, хотя подключение к базе работает

## Подготовка на другом компьютере

1. Установить Python 3.12 и создать `.venv`; установить зависимости из `requirements-lock.txt`
2. Скачать архив Windows x64 из [официального раздела PostgreSQL](https://www.postgresql.org/download/windows/) через ссылку на [EDB binaries](https://www.enterprisedb.com/download-postgresql-binaries), распаковать в `data/postgres-runtime`, чтобы появился `pgsql/bin`
3. Инициализировать новый кластер командой ниже. Ввод пароля интерактивный; записать его в игнорируемый `.env`

```powershell
.\data\postgres-runtime\pgsql\bin\initdb.exe -D data/postgres-cluster -U altitude_user -A scram-sha-256 -W -E UTF8 --locale=C
powershell -File scripts/postgres.ps1 start
.\data\postgres-runtime\pgsql\bin\createdb.exe -h 127.0.0.1 -p 55432 -U altitude_user -W altitude_pipeline
```

В `.env` задать `DATABASE_URL=postgresql://altitude_user:<пароль>@127.0.0.1:55432/altitude_pipeline`. Специальные символы пароля в URL требуют кодирования; можно выбрать случайный пароль из букв и цифр. Пользователь altitude_user владеет локальным кластером: это учебная конфигурация, отдельная роль с ограниченными правами нужна для дальнейшего развертывания

4. Подготовить локальные данные командой `scripts/audit_source.py`, затем выполнить `scripts/database.py` дважды. На втором запуске `inserted` должно быть нулем, `roundtrip_exact` – true

Запуск на новом компьютере целиком еще не проверен. В этом проекте проверены status, stop, start и повторная загрузка после перезапуска. Пять тестов прошли, включая откат при конфликте данных и при ошибке итоговой сверки

## Что объяснить на интервью

Идемпотентность означает, что повтор одинакового импорта не меняет число строк. `ON CONFLICT DO NOTHING` само по себе недостаточно: оно может скрыть изменение данных по существующему ключу. Поэтому сначала сравниваем все значения, затем пропускаем только идентичные записи

Split хранится отдельно и неизменен. Загрузка не выбирает новые дни, не перераспределяет train/validation/test и не обучает модель. Секунды Unix сохраняются без округления, чтобы точно повторить исходные признаки; для календарных SQL-запросов используется явное преобразование времени
